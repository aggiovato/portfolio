# Internationalisation (i18n)

The site is multilingual: **English** (default, no prefix) and **Spanish** (`/es/`). Built on
Astro's i18n routing with static generation; no runtime library. Spec §17 sets the constraints.

## How it works

| Piece       | Location                         | Role                                                                        |
| ----------- | -------------------------------- | --------------------------------------------------------------------------- |
| Locale list | `src/i18n/config.ts`             | `locales`, `defaultLocale`, names. Imported by `astro.config.mjs`.          |
| Routing     | `astro.config.mjs` → `i18n`      | `prefixDefaultLocale: false`: `/work/` (en), `/es/work/` (es).              |
| Pages       | `src/pages/[...locale]/`         | One file per page; `localeParams()` generates every locale.                 |
| UI strings  | `src/i18n/ui/<locale>.ts`        | Flat dotted keys. `en.ts` defines the key set; others are typed against it. |
| Helpers     | `src/i18n/index.ts`              | `resolveLocale`, `useTranslations`, `localizePath`, `alternatesFor`.        |
| Content     | `src/content/projects/<locale>/` | One `.mdoc` per locale, **same file name and slug** in every locale.        |

## In a page or component

```astro
---
import { localizePath, resolveLocale, useTranslations } from '../i18n';

const locale = resolveLocale(Astro.currentLocale);
const t = useTranslations(locale);
---

<a href={localizePath('/work/', locale)}>{t('hero.primaryCta')}</a>
<p>{t('hero.identity', { role: t('site.role'), focus: t('site.focus') })}</p>
```

- **Never hard-code user-visible text**: headings, buttons, `aria-label`, `alt` of UI icons,
  `<title>`, meta descriptions, empty states. Add a key to `en.ts` and every other dictionary
  (`astro check` fails if one is missing; a unit test checks placeholders match).
- **Never write internal links as literals** (`href="/work/"`): use `localizePath(path, locale)`,
  where `path` is the default-locale path. For case studies use `projectPath(project)`.
- Interpolate with `{name}` placeholders; do not concatenate translated fragments when word order
  can change between languages. Split around markup only when unavoidable (`about.nameBefore/After`).
- Formatting dates or numbers: `Intl` with the current `locale`.
- Exempt: decorative code in the hero (`mission` object, flight notes, the `~/work` path labels),
  brand and person names, technology names. They read as code and stay in English.

## Pages and SEO

- `BaseLayout` sets `<html lang>`, `og:locale`, `hreflang` alternates and `x-default` (English).
- By default every page exists in every locale (`alternatesFor`). A page that may be missing in a
  locale passes `alternates` explicitly; case studies use `getProjectAlternates(project)`.
- The switcher in `SiteHeader` goes to the same page in the other locale; if it does not exist
  (untranslated case study) it goes to that locale's `/work/`, never always to the home (§17).
- `404.astro` is rendered once in the default locale (static hosts serve one `/404.html`).

## Content translations

- Translation = same file name in another locale folder (`en/yrest.mdoc` ↔ `es/yrest.mdoc`) with the
  **same `slug`**. `assertTranslationParity` fails the build otherwise.
- Translate prose, `title`, `summary`, `tagline`, `role`, `periodLabel`, `categories`, stack
  `rationale`, `alt` and `caption`. Keep `slug`, image paths, links, `stack[].name/layer`,
  `projectType/Status`, `featured*` and dates identical.
- Untranslated case studies have no `/es/` page; listings show the English original with an
  "In English" note and `lang`/`hreflang` on the link. Do not create a copy just to fill the gap.
- Machine or AI translations are drafts: keep `publicationStatus: draft` until the author reviews them.

## Adding a locale

1. Add it to `locales` (and `localeNames`, `ogLocales`) in `src/i18n/config.ts`.
2. Create `src/i18n/ui/<locale>.ts` typed as `UiDictionary` and register it in `ui/index.ts`.
3. Update `localeParams` expectations in `tests/unit/i18n.test.ts` and add the locale to e2e paths.
4. Translate content into `src/content/projects/<locale>/` (optional; fallbacks cover the rest).

Use the `translate-content` skill for content and dictionary work.

## Checklist

- [ ] No literal copy or literal internal links in the change
- [ ] New keys exist in every dictionary with the same placeholders
- [ ] The page works at `/…` and `/es/…`; hreflang and switcher point to real pages
- [ ] Content translations keep file name and slug
